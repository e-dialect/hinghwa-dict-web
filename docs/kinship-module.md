# 亲戚计算模块 v1（Phase 3）

两端页面直接使用共享纯引擎，不再把“当前关系角色”当成一个已经确定的人物。数据仍是 Phase 2 的版本化 JSON，本阶段没有改变词条、关系边或来源事实。分阶段工作见 [Issue #188](https://github.com/e-dialect/hinghwa-dict-web/issues/188)。

## 模块与状态

|文件|职责|
|---|---|
|src/data/kinship/v1/engine.mjs|纯关系引擎、符号人物身份、父母/配偶/同胞及年龄约束|
|src/data/kinship/v1/view-model.mjs|按钮预演、路径/候选/人物来源提示、词条状态投影及顺序加载|
|src/data/kinship/v1/vue-mixin.mjs|两端同形的组件事件、会话与请求归属|
|Web RelativeSelect.vue / uni tools/relative.vue|平台控件与词条展示，不另写关系算法|

角色 ID、人物 token、词条 ID 分开。一个“兄亲”角色可以对应多名兄长；候选选择使用 `candidateId`，不能用角色名称或列表下标替代。候选显示首次出现的步骤/路径，区分此前人物和其他同称人物；选择后及撤销后仍显示当前人物来源。

`session.path` 只计算关系步数，选择不增加一步。撤销恢复上一个关系步骤之前已经选定的人物及关系图。根节点撤销安全；清空保留显式性别；改变显式性别清空路径。未指定性别时可以有条件分支，选择后产生的推断性别不会偷偷保存为显式设置。

默认上限为 15 个关系步骤。无效选择、不支持的操作或达到上限不会删掉已有路径和结果。按钮通过纯引擎预演判断是否可前进，因此静态关系字段为空但人物身份已确定的父母回溯仍可使用。

## 模型与覆盖边界

本版本采用同父母同胞、父母分角色及已知当前配偶作为子女共同父母的限定模型。义亲、继亲、异父母同胞、婚姻变更历史、合称继续遍历等关系不在推导范围。它不是对所有实际家庭结构的完整模型，也不能自动校正关系图未收录或写错的角色/词形。

如果静态图没有完整收录，而引擎只找到路径中已经确定的人物，`hasUnlistedPossibilities` 会要求显式选择，即使只显示一个候选也不会自动当作唯一完整答案。选择后保留覆盖不足提示；后续路径步骤也保留“仅已知人物”标记。

例如“母→父→兄→弟”可返回已知外祖父，但图可能没有收录其他兄弟，因此只能说这是当前已知的一种可能。已明确绑定的唯一父母或配偶则按身份回溯，不凭词形重推一遍。

页面的计算说明问号保留这些模型边界，默认不展开；覆盖不足、需选择人物等当前操作相关提醒仍直接显示。关系图及称谓使用方式仍需语言学校订；引擎测试通过不代表每一种现实亲属关系都已覆盖。

## 词条与投稿

词条显示直接由规范 `terms.status` 决定：

- bound：使用有词库 ID 的绑定请求词条；失败保留原正整数 ID、原词形和 loadError，显示重试。快照绑定不等于完成语言学审校。
- missingWord：显示资料中的真实方言词形，明确词库对应仍待确认，不发送空 ID 请求。
- rolePending：显示“方言称谓待核定”状态和关系说明，不把普通话角色占位伪装成方言词形，不发送词条请求。

加载保持声明顺序。选择、撤销、清空或改变性别时，旧请求失去写回归属；组件销毁、卸载或页面卸载后也不能写回结果。异步顺序不影响已经选定的人物。

两端常驻“有更多说法？补充词条”入口；纸面词形整理和投稿流程说明收在旁边问号中。不会把普通话占位预填为新词形。投稿目前仅进入词库，审核后还需维护者手动关联计算器，不自动发布关系映射；完整闭环留给乡声集盒。

界面采用紧凑性别选项、两行关系按钮和独立结果区。角色标签、拼音和释义为辅助文字；候选身份保留简短的首次出现步骤，首次到达新人物时不重复解释。uni 的紧凑词条列表是显式 opt-in，其他页面默认布局不变。

uni 亲戚页使用可选的 background 词条请求，由结果区显示加载和重试，不弹全屏遮罩，也不取消其他请求的全局 loading。旧页面的默认请求行为不变。

## 测试与 CI

无需新增依赖：

```sh
npm run check:kinship-module
# Web
npm run check:kinship-module -- ../hinghwa-dict-uni-app
# uni
npm run check:kinship-module -- ../hinghwa-dict-web
```

分别可运行 `check:kinship`（数据契约）、`check:kinship-engine`（纯引擎）、`check:kinship-ui`（组件事件与加载）。

全套包含：

- Phase 2 schema、110 个冻结 ID、旧导出对象兼容 SHA、19 个无效数据负例。
- 32 个纯引擎单测、12 个真实 110 角色数据测试；四步有限展开检查 13,770 次操作、15,023 个候选图。
- 固定种子 1949 的 1,000 条最多 15 步路径，检查 22,574 个候选图的身份、年龄与亲缘环约束。
- 每端 18 个实际组件导出/共享 mixin 事件及异步集成测试，覆盖选择/撤销/清空/性别/条件/上限/未知操作/覆盖不足/同称人物首见步骤/静态空边回溯/词条状态/重试/竞态/销毁，以及说明默认折叠、简短身份和移动端后台请求参数。
- uni 另有 7 个真实请求层/词条服务测试，覆盖默认 loading、background 成功与网络失败、401/403/404/500/503、原 noPrompt 行为及词条解包。
- 两端规范数据与三份生产模块、所有新测试/检查脚本字节一致。

组件脚本测试是实际 SFC export / 共享 mixin 的 event harness，不运行 DOM 或真实小程序，不能替代浏览器或真机验收。

2026-10-13：主代理以本地产物、75 个只读 SQLite 词条 ID 夹具并阻断生产 API，完成精简界面后的 Web 与 uni H5 真实浏览器验收。覆盖问号展开/收起、人物来源、歧义/撤销/性别、同称身份与选后提示、缺覆盖、待核/待补词形/女儿/外孙、503 重试和慢旧请求。uni 慢词条请求期间可继续选关系，迟到结果不能覆盖新结果。两端首屏截图已检查，无横向溢出。Web、H5、mp-weixin 生产编译均成功；未验证真实音频、登录、微信真机或正式发布，未写入生产词库。

CI 中亲戚模块路径、相关检查和 package.json 变更触发本地全套。单端 Vue 模板或仅 npm script 调整不强制另一仓库存在同名分支；任何共享数据、引擎、view-model、mixin、检查脚本或 workflow 变更均要求配对 PR。配对检出使用 `KINSHIP_PEER_REF` 或 PR 同名分支，缺失/字节不同会失败，不自动退回 master。

master 只执行本地全套，不依赖另一仓库的合并先后顺序。两端合并完成后仍应刷新两个 master checkout，手动运行带 peer 参数的全套核对最终状态。

## 构建与验收入口

Web：

```sh
npm run build
```

产物为 `dist`，history 路由为 `/tools/Relative`。

uni H5 构建前，应临时用文件补丁把 manifest.json 的 h5.router.base 和 h5.publicPath 改成 `/`，运行 `node_modules/.bin/uni build`，最后恢复原占位。只传 `--base=/` 不足以覆盖运行时 router base。现有 npm 脚本中的 GNU sed 写法不作为 macOS 手工构建方式。

H5 产物为 `dist/build/h5`，history 路由为 `/pages/tools/relative`。微信编译使用 `node_modules/.bin/uni build -p mp-weixin`，不改变 appid；产物为 `dist/build/mp-weixin`。构建成功只证明编译兼容，不是微信真机或发布验收。
